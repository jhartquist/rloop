When a task completes successfully, the session should update the task's `completed: true` field in the task markdown file and include that change in the commit.

## Current Behavior

`finish_successful_task()` in `session.rs` commits the agent's code changes but does NOT update the `completed` field in the task file (`.rloop/tasks/XX.md`). The task file still says `completed: false` after a successful run.

## Required Changes

1. Add a `mark_completed()` function in `task.rs` that reads a task file, replaces `completed: false` with `completed: true` in the frontmatter, and writes it back.
2. In `finish_successful_task()` in `session.rs`, call `mark_completed()` on the task's source path INSIDE the worktree before the commit. The task files exist in the worktree since the worktree is a full checkout.
3. The worktree path to the task file is: `{worktree.path}/.rloop/tasks/{task_id:02}.md`.

## Acceptance Criteria

- After a successful task run, the task file on the session branch has `completed: true`.
- The completed-field update is part of the same commit as the agent's changes.
- The function handles edge cases: already completed, missing file (returns error).
- Unit test for `mark_completed()` that verifies the field is flipped.
- Existing tests still pass.
