# Research sqlx + Supabase integration patterns and gotchas

## Context

sqlx will be the Rust database layer for the brain. Supabase runs Postgres but adds its own schemas, extensions, and connection pooling (PgBouncer/Supavisor). There are known gotchas when using sqlx with Supabase specifically.

## Research Questions

1. **Known gotchas**: What breaks or behaves unexpectedly when using sqlx with Supabase? Connection string format? SSL requirements? Auth schema conflicts? Extension availability?

2. **Compile-time checked queries**: How does `sqlx::query!()` work with a local Supabase instance? Does it connect to the Supabase Postgres directly or through the pooler? What's the `DATABASE_URL` format?

3. **Connection pooling**: Supabase uses Supavisor (or PgBouncer in older setups). How does this interact with sqlx's own connection pool? Should the Rust app connect to the pooler or directly to Postgres?

4. **Offline mode**: sqlx supports `sqlx prepare` for CI (no live DB needed). How does this work with Supabase-specific types or extensions?

5. **Testing patterns**: How to run tests against Supabase Postgres? Test database per run? Transactions that roll back? How fast is the cycle?

6. **Type mapping**: How do Postgres arrays (`INTEGER[]`), JSONB, TIMESTAMPTZ, and UUID map to Rust types in sqlx? Any surprises with Supabase's version of Postgres?

## Deliverable

Write findings to `docs/research/sqlx-supabase.md`. Include code snippets for connection setup, query patterns, and any workarounds for gotchas.

## Acceptance Criteria

- All known gotchas documented with workarounds
- Working connection string format for local Supabase
- Recommendation on direct Postgres vs pooler connection
- Type mapping table for our schema types
- Test strategy recommendation
