Model has Display via strum but no FromStr. The CLI defines a hand-rolled ModelArg wrapper in main.rs:96-118 for case-insensitive parsing. Worse, Model serde deserialization is case-sensitive — "opus" in config.toml fails but --model opus on CLI works.

## What to do

- Add `EnumString` derive from strum to `Model` with `#[strum(ascii_case_insensitive)]`
- Remove the `ModelArg` wrapper from main.rs and use `Model` directly in Clap
- Add a custom serde deserializer for Model that is case-insensitive (or use `#[serde(rename_all = "PascalCase")]` with aliases)
- Add tests for case-insensitive parsing: "opus", "Opus", "OPUS" should all work
- Ensure config.toml accepts lowercase model names
- Ensure all tests pass

## Why

BuiltinTool already does this correctly with EnumString. Model should follow the same pattern. The case-sensitivity inconsistency between CLI and config file is a UX bug.
