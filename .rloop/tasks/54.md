main.rs:682 uses `.map_err(|_| anyhow!("task {target} not found"))` which discards the original error. If the task file exists but has invalid YAML, the user sees "not found" instead of the real parse error.

## What to do

- Replace `.map_err(|_| anyhow!("task {target} not found"))` with `.with_context(|| format!("failed to load task {target}"))`
- This preserves the original error (e.g., YAML parse failure) as context
- Check for other `.map_err(|_| ...)` patterns in main.rs that discard errors
- Ensure all tests pass

## Why

Swallowing real errors creates confusing UX. A user with a YAML syntax error in their task file will be told the task "doesn't exist" instead of seeing the parse error.
