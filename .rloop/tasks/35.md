session.rs:341-351 uses a raw `*const E` wrapped in manual `Send`/`Sync` impls to smuggle the executor reference across async boundaries. The safety argument holds today but is fragile — any future refactoring to `tokio::spawn` or early returns would create unsoundness.

## What to do

- Replace `StepExecutorRef<E>(*const E)` with `Arc<E>`
- Remove the `unsafe impl Send/Sync` blocks
- Update `execute_dag` to accept `Arc<E>` or wrap the executor in `Arc` at the call site
- Remove the `unsafe fn get(&self)` method
- Update all call sites in session.rs that use `StepExecutorRef`
- Ensure all 222 tests still pass

## Why

This is the #1 thing experienced Rustaceans will flag. `unsafe` for performance in a system that makes Claude API calls is unjustifiable. The `Arc` overhead is negligible.
