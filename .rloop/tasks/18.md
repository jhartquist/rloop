Research how to add LLM-based verification as an alternative or supplement to command-based verification. Today verification runs shell commands (e.g. `cargo test`). The goal: optionally have a second LLM pass review the agent's work and judge whether the task was actually completed correctly.

## Approach

Use parallel research agents to explore these aspects simultaneously:

1. **Verification agent design** — What the LLM verifier sees (diff, full files, task description, acceptance criteria). Whether it runs in the same worktree or gets a read-only view. What tools it needs (Read, Glob, Grep, Bash for running tests — but NOT Write/Edit). How to structure its judgment (pass/fail with reasoning, or a score, or a structured checklist). Whether it can request the task agent to fix things or just reports.
2. **Integration with existing verification** — Whether LLM verification replaces or supplements command verification. Ordering (commands first then LLM, or LLM only, or both). How to configure it per-task and per-project. Whether it uses the same model as the task agent or a different one (e.g. task runs on Sonnet, verification on Opus).
3. **Shared query infrastructure** — This is the second ancillary agent feature (alongside task enhancement). Both need a lightweight LLM query path that shares infrastructure with the main step executor but has different tools and prompts. Research what a shared `rloop_query` abstraction looks like that serves both use cases and future ones.
4. **Cost and latency** — LLM verification adds cost and time to every task. Research strategies to minimize this (shorter context, targeted diffs only, cheaper model for verification, caching). Whether verification should be optional per-task via frontmatter. How to report verification cost separately in session metrics.

## Output

Write `research/03-llm-verification.md` with sections for:
- Multiple approaches to LLM verification (full review, diff-only review, checklist-based, multi-model)
- Trade-offs for each (accuracy, cost, latency, complexity)
- Relationship to the shared ancillary agent pattern from task 16
- Open questions to resolve before implementation (when to use LLM vs command verification, who decides pass/fail if they disagree, how to handle false negatives)
