## Goal

Add a lightweight merge-fix agent that attempts to resolve merge conflicts before marking a task as failed. Converts the two-phase merge (rebase or fail) into the three-phase merge (rebase → merge-fix agent → fail).

## Reference

Read `research/06-parallel-dag-implementation.md` for the full design spec. Uses `run_query` from `query.rs` (already exists). Phase 2 (task 32) must be complete — this extends the merge pipeline.

## Changes

### 1. New git helpers

In `git.rs`, add:
- `merge_no_commit(repo, branch) -> Result<bool>` — runs `git merge <branch> --no-commit`, returns true if clean, false if conflicts
- `merge_abort(repo) -> Result<()>` — runs `git merge --abort`
- `has_conflict_markers(repo) -> Result<bool>` — runs `git diff --check`, returns true if conflict markers remain

Unit test all three with real git repos.

### 2. Merge-fix agent function

New function (in `session.rs` or a new `merge.rs` module):

```rust
async fn attempt_merge_fix(
    repo: &Path,
    worktree_path: &Path,
    task: &Task,
    session_branch: &str,
    config: &Config,
    logger: &EventSender,
) -> anyhow::Result<bool>  // true = resolved, false = gave up
```

Steps:
1. In worktree: `git merge <session-branch> --no-commit` (leaves conflict markers)
2. Build prompt: describe the conflict, include task description, instruct agent to resolve markers
3. Call `run_query` with model=Sonnet, tools=[Read, Edit, Bash, Glob, Grep], cwd=worktree
4. After agent completes: check `has_conflict_markers()`
5. If clean: `git add -A && git commit`, return true
6. If not clean: `merge_abort()`, return false

### 3. Integration into merge pipeline

In the merge serialization code (from Phase 2), after rebase fails:
1. `rebase_abort()`
2. `attempt_merge_fix()`
3. If resolved: fast-forward session branch to worktree branch, log success
4. If not resolved: mark task as failed, preserve branch, log `MergeFailed`

### 4. New events

In `log.rs`, add:
- `Event::MergeFixStarted { task_id }`
- `Event::MergeFixSucceeded { task_id, cost_usd }`
- `Event::MergeFixFailed { task_id, reason }`

Add terminal printing and JSONL serialization.

### 5. Merge-fix agent prompt

The prompt should be clear and constrained:
- Describe what happened (rebase conflict during parallel execution)
- Show the task description so the agent understands intent
- Instruct: read conflicted files, resolve markers, verify with `git diff --check`
- Agent has full Read/Edit/Bash/Glob/Grep tools in the worktree

## Approach

Use subagents: (a) git helpers + tests, (b) merge-fix function + events + integration. The merge-fix agent itself is a `run_query` call — the complexity is in the git plumbing and the prompt, not the agent infrastructure.

## Acceptance Criteria

- Merge-fix agent invoked automatically when rebase fails
- Simple conflicts resolved (two tasks modify different parts of same file)
- Irreconcilable conflicts: agent gives up, task marked as failed, branch preserved
- Events logged: MergeFixStarted, MergeFixSucceeded/MergeFixFailed
- Cost of merge-fix agent visible in session output
- All existing tests pass
- `cargo clippy --all-targets -- -D warnings -W clippy::pedantic` clean
