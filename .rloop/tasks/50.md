VerificationCommands(pub Vec<String>) exposes its inner vec. Code accesses .0 directly (e.g., cmds.0.join("; ")).

## What to do

- Make the inner field private: `pub struct VerificationCommands(Vec<String>)`
- Implement `Deref<Target=[String]>` so consumers can call .len(), .join(), .iter() etc.
- Update all .0 access sites:
  - task.rs tests: `task.verification.as_ref().unwrap().0.len()` → `.len()`
  - tools.rs:204: `run_verification(&v.0, ...)` → `run_verification(&v, ...)`
  - main.rs:709: `cmds.0.join("; ")` → `cmds.join("; ")`
- Add a `Display` impl that joins with "; "
- Ensure all tests pass

## Why

Accessing .0 on a newtype defeats encapsulation. Deref provides a clean API while maintaining the newtype's purpose.
