TaskId is sorted by accessing .0 directly (task.rs:167: `tasks.sort_by_key(|t| t.id.0)`). The CLI manually does `TaskId(task_id)` from a raw u32.

## What to do

- Add `PartialOrd, Ord` to TaskId derives
- Replace `tasks.sort_by_key(|t| t.id.0)` with `tasks.sort_by_key(|t| t.id)`
- Add a `FromStr` implementation for TaskId that parses a u32
- Simplify CLI parsing to use TaskId::from_str where appropriate
- Ensure all tests pass

## Why

Deriving Ord makes sorting natural. FromStr makes parsing idiomatic. Accessing .0 to sort is a code smell when Ord could be derived.
