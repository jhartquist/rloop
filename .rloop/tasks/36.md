Every successful task emits `TaskCompleted` twice: once in `run_with_retries` (session.rs:521) and again in `execute_task_in_worktree` (session.rs:451). The test even documents it: `"two TaskCompleted per successful task"`.

## What to do

- Remove the `TaskCompleted` emission from `run_with_retries` — let `execute_task_in_worktree` be the single source of truth
- Update the integration test assertion in session_tests.rs that expects `task_completes.len() == 6` (should be 3 for 3 tasks)
- Verify the session log JSONL output has exactly one TaskCompleted per successful task
- Ensure all tests pass

## Why

Duplicate events muddy session logs and confuse programmatic consumers. Log analysis cannot distinguish "step succeeded" from "task committed" when both use the same event type.
