Several modules in lib.rs expose internal implementation details as public API:

- `tools` — MCP tool plumbing, only used by step.rs
- `merge` — only used by session.rs
- `lock` — only used by session.rs
- `testing` — RecordingExecutor/PlaybackExecutor test utils in production API

## What to do

- Change `pub mod tools` to `pub(crate) mod tools`
- Change `pub mod merge` to `pub(crate) mod merge`
- Change `pub mod lock` to `pub(crate) mod lock`
- Gate `testing` behind `#[cfg(any(test, feature = "testing"))]` or make it `pub(crate)`
- If any of these are used by integration tests via `rloop::module`, add re-exports or adjust test imports
- Keep `template` as `pub` since examples use it
- Ensure all tests, examples, and clippy pass

## Why

Library consumers should not see session-internal plumbing. Test infrastructure should not ship in production builds. A wide public API surface signals "not carefully curated."
