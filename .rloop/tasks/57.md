Events are serialized directly with no timestamp envelope. The SPEC says "Timestamps on everything" and VISION.md says "Observable Everything." Without real timestamps, the session JSONL file cannot support duration analysis or the outer learning loop.

The session show command currently uses event index as a fake time proxy (main.rs:794-808), which is actively misleading.

## What to do

- Add a `timestamp` field to the JSONL output. Two approaches:
  a) Add `timestamp: chrono::DateTime<Utc>` to each Event variant (invasive)
  b) Wrap events in a `LogEntry { timestamp, event }` envelope struct (cleaner)
- Option (b) is preferred — keeps Event clean and adds timestamp at the serialization layer
- Update `SessionLogger::log()` to wrap events in `LogEntry` before serializing
- Update `load_events()` to deserialize `LogEntry` envelopes (with fallback for old format)
- Update `cmd_session_show` to use real timestamps instead of event index
- Update tests that parse JSONL to handle the envelope
- Ensure all tests pass

## Why

This is foundational to the project's stated goals. Without timestamps, session logs cannot support trajectory analysis, performance optimization, or the outer learning loop described in VISION.md.
