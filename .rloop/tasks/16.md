Research how to add an optional LLM pass when creating tasks via `rloop task new`. The goal: a user types a rough description, and an agent rewrites it into a well-structured task with a proper title, acceptance criteria, and clean markdown.

## Approach

Use parallel research agents to explore these aspects simultaneously:

1. **Agent query architecture** — How to share query infrastructure with the main step executor (ClaudeClient, streaming, MCP tools) while having different tool sets, prompts, and no structured output. What can be reused vs. what needs a lighter-weight query path.
2. **UX and CLI design** — Flag naming (`--enhance`, `--refine`, `--ai`, or a config default). Whether enhancement happens inline (blocking) or writes a draft for review. How to show the before/after. Whether the title should be auto-generated if not provided.
3. **Prompt engineering** — What system prompt and examples produce the best task rewrites. Whether to include the existing task corpus as few-shot examples. How to handle the case where the user's description is already good enough.
4. **Broader ancillary agent pattern** — This is the first of several 'single LLM query' features (task enhancement, LLM verification, etc.). Research whether to build a general `rloop_query(prompt, tools, config) -> String` helper that all these features share.

## Output

Write `research/01-task-enhancement.md` with:
- Multiple approaches considered (inline enhancement, draft-and-confirm, config-driven defaults, separate `rloop task refine` command)
- Trade-offs for each approach (latency, cost, user control, complexity)
- Open questions to resolve before implementation (e.g., should enhancement be opt-in or opt-out? Should it generate verification commands? Should it infer dependencies?)
