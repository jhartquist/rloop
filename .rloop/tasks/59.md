## Problem

`merge_with_fix` runs `git rebase <session_branch> <task_branch>` in the main repo worktree. This checks out the task branch in the user's working directory, mutating their checkout. Even with parallel=1, every task merge cycles main through: parent_branch → task_branch → parent_branch. If the process crashes mid-rebase, main is left on a random task branch.

This violates the design principle: the main worktree is never modified during a session.

## Root Cause

The task worktree is removed (cleanup_worktree_preserve_branch) before the merge, freeing the branch. Then rebase runs from the main worktree because that's the only worktree available. The fix: don't remove the task worktree before merge — rebase from inside it.

## Changes

### session.rs (execute_dag, success path ~line 252)
- Remove the call to `cleanup_worktree_preserve_branch` before merge
- Pass the task worktree path to `merge_with_fix`
- Move worktree cleanup to AFTER merge (both success and failure paths)
- On merge success: `cleanup_worktree(repo, &result.worktree)` (full cleanup including branch)
- On merge failure: `cleanup_worktree_preserve_branch(repo, &result.worktree)` (keep branch for recovery)
- Remove the manual `git branch -D` after merge success (cleanup_worktree handles it)

### merge.rs (merge_with_fix)
- Add `worktree_path: &Path` parameter
- Remove `parent_branch: &str` parameter (no longer needed)
- Phase 1 rebase: run `git rebase <session_branch>` with cwd=worktree_path (not repo)
- On rebase success: `fast_forward_ref(repo, session_branch, task_branch)` then return Ok
- On rebase failure: `rebase_abort(worktree_path)` (not repo) then proceed to merge-fix
- Remove ALL `git checkout parent_branch` calls (lines 188, 211, 233)

### git.rs
- Update `rebase` and `rebase_abort` if needed to clarify they run in a directory (they already take a generic path, should be fine)

## Acceptance Criteria
- `git rebase` never runs with cwd=repo (main worktree)
- No `checkout parent_branch` calls in merge.rs
- `merge_with_fix` no longer accepts parent_branch parameter
- Main worktree stays on parent_branch throughout the entire session
- All existing tests pass
- Clippy pedantic clean
