## Problem

`finalize_session` does `git checkout parent_branch` before the ff-only merge. After tasks 59-60, the main worktree is never modified during the session, so we're already on parent_branch. The checkout is redundant but was a safety net for the old rebase-in-main flow.

## Changes

### session.rs (finalize_session)
- Remove the `git checkout parent_branch` call before merge (we're already on it)
- Keep the `git merge --ff-only session_branch` — this is correct, it updates both the ref and working tree in one shot, which is what auto-merge should do
- Add an assertion/debug check that we're on parent_branch before auto-merge (optional, for safety)

## Acceptance Criteria
- No redundant `git checkout` in finalize_session
- Auto-merge still works correctly (ff-only merge updates ref + working tree)
- All existing tests pass
