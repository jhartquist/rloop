# Design Cargo workspace restructuring for brain/worker/CLI

## Context

rloop is currently a single crate (`rloop/`) with one binary and one library. Milestone 1 introduces a second binary (the brain daemon) and eventually a third (the worker). We need to restructure into a Cargo workspace.

## Research Questions

1. **Workspace layout**: What's the right crate split? Options:
   - `rloop-core` (shared types: Task, Event, Config, etc.) + `rloop` (CLI) + `rloopd` (brain)
   - `rloop` (library with everything) + `rloop-cli` + `rloopd`
   - Flat workspace with feature flags instead of separate crates
   - Something else?

2. **What's shared**: Which current types need to be shared between brain and CLI? Events, task types, config types, model enum. What stays private to each binary?

3. **Migration path**: How to restructure without breaking the existing crate? Can we do it incrementally (add workspace.toml, move things gradually) or is it a big-bang refactor?

4. **Binary names**: `rloop` (CLI stays the same), `rloopd` (brain daemon), `rloop-worker` (future). How to configure these in Cargo.toml?

5. **Test organization**: Where do integration tests live? Per-crate `tests/` or a shared `tests/` workspace member? What about the existing 267 tests?

6. **Dependencies**: Which deps go where? sqlx only in brain, claude-agent-sdk only in worker/CLI, axum only in brain, etc. Minimize dependency overlap.

## Deliverable

Write findings to `docs/research/workspace-design.md`. Include the proposed directory layout and a migration plan.

## Acceptance Criteria

- Concrete workspace layout decided (directory tree)
- Clear assignment of current modules to crates
- Migration plan (incremental vs big-bang, steps)
- Dependency assignment per crate
- Existing tests accounted for
