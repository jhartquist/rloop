# Add title field to tasks

Add a `title` field to the task frontmatter so tasks have a short descriptive name in addition to their full markdown description.

## Current State

- Task struct (task.rs:25-35) has: id, model, depends_on, verification, completed, description, source_path
- TaskFrontmatter (task.rs:72-83) has: id, model, depends_on, verification, completed
- No title field exists
- `cmd_list()` in main.rs shows the first non-empty line of description as a summary
- `cmd_task_new()` in main.rs takes a `description` argument

## What to do

### 1. Add `title` field to Task and TaskFrontmatter

```rust
pub struct Task {
    pub id: TaskId,
    pub title: String,          // NEW
    pub model: Model,
    // ...
}
```

```rust
struct TaskFrontmatter {
    id: u32,
    #[serde(default)]
    title: String,              // NEW - optional, defaults to empty
    // ...
}
```

### 2. Add `--title` to `rloop task new` CLI

```
rloop task new --title "Implement audio preprocessing" "Full description here..."
```

Write the title into the frontmatter:

```yaml
---
id: 3
title: Implement audio preprocessing
model: Opus
---
```

### 3. Update `rloop list` to show titles

If a task has a title, show it instead of the first description line:

```
[    ] 00 - Add input validation to MCP tools
[done] 01 - Implement audio preprocessing
[    ] 02 - (no title, shows first line of description)
```

### 4. Update test helpers

Update `make_task()` in task.rs tests and any other test helpers to include the title field.

## Acceptance Criteria

- Task struct has a `title: String` field
- TaskFrontmatter deserializes the title (optional, defaults to empty string)
- `rloop task new --title "..." "description"` writes title to frontmatter
- `rloop list` shows title when available, falls back to first description line
- Existing task files without title still parse correctly (backward compatible)
- Tests cover title parsing, missing title, and display
