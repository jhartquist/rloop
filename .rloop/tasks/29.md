# Add rloop session show command with elapsed time display

Add a new CLI subcommand `rloop session show <session-id>` that loads and displays session events from `.rloop/sessions/{session-id}.jsonl` with elapsed time information.

## Context

Session logs are already written to `.rloop/sessions/{session_id}.jsonl` as JSONL (one JSON event per line). The `load_events()` function exists in `log.rs` to parse these files. Currently there's no way to review past session logs from the CLI.

## Requirements

### CLI Structure

Add a new top-level `Session` subcommand to `main.rs`:

```rust
#[derive(Subcommand)]
enum Command {
    Init,
    Run { /* ... */ },
    Task { /* ... */ },
    Session {
        #[command(subcommand)]
        action: SessionAction,
    },
}

#[derive(Subcommand)]
enum SessionAction {
    /// Display a session log with elapsed time
    Show {
        /// Session ID (e.g., 20250206-143022)
        session_id: String,
    },
    // Future: List (list all sessions)
}
```

### Display Format

For each event, print:
- **Elapsed time** from session start (e.g., `+0s`, `+12s`, `+1m 34s`)
- **Event type** and details (use existing `SessionLogger::print()` as reference)

Example output:
```
Session 20250206-143022

+0s       ▶ Session 20250206-143022
          Date:   2025-02-06 14:30:22 PST
          Target: task 05
          Branch: main → rloop-05

+2s       → Task 05  step 1  model: claude-sonnet-4-5  cc: abc-123
+15s        CALL  Read src/lib.rs
+16s         RES  Read ok (142 lines)
+18s        CALL  Edit src/lib.rs
[...]
+1m 23s   ✓ task 05 — added feature X
+1m 24s   ■ session complete → branch rloop-05
```

### Implementation Details

1. **Load events** using `crate::log::load_events()`
2. **Extract session start time** from the first `SessionStarted` or `SessionBanner` event (these don't have timestamps in the events themselves, but are always first)
3. **Track elapsed time** by processing events sequentially and computing duration from event order
4. **Format elapsed time** as:
   - `+Xs` for seconds < 60
   - `+Xm Ys` for 60+ seconds
   - Right-aligned to consistent width (e.g., 8 chars: `+1m 23s` or `     +0s`)
5. **Print events** using similar formatting to `SessionLogger::print()` but with elapsed time prefix

### Notes on Timestamps

Events in the JSONL don't currently have timestamps — they're written sequentially as they occur. For this task:
- Treat the file as ordered chronologically
- Compute relative time from event order (first event = +0s)
- If we need actual timestamps in the future, that would be a separate enhancement

For now, show relative timing based on event sequence. This is sufficient for understanding session flow and identifying slow steps.

## Acceptance Criteria

- [ ] `rloop session show <session-id>` loads and displays events from `.rloop/sessions/{session-id}.jsonl`
- [ ] Each event is prefixed with elapsed time from session start (e.g., `+12s`, `+1m 34s`)
- [ ] Elapsed time is right-aligned and consistently formatted
- [ ] Events use similar formatting to the live stream output (colored icons, structured layout)
- [ ] Command fails gracefully if session ID not found
- [ ] `cargo clippy --all-targets -- -D warnings` passes
- [ ] Manual test: run a session, then view its log with `rloop session show`
