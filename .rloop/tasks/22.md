Fix the context_usage MCP tool which currently returns hardcoded 0.0%. Add a ContextTracker struct to step.rs that tracks the most recent assistant message's token usage (NOT cumulative sums). The formula is: context_pct = (input_tokens + cache_read_input_tokens + cache_creation_input_tokens + output_tokens) / 200_000 * 100. Wire this into the context_usage tool via Arc<AtomicU32> shared state (store f32 bits as u32), matching the existing Arc<AtomicBool> pattern used for the stop flag. Update the stream processing in execute_step to update the ContextTracker after each Message::Assistant, then store the percentage in the atomic. Add deduplication based on findings from task 21. Remove or fix compute_context_usage — it should NOT be called from the Result message. The Result message is for final billing totals only; context tracking happens in real-time during the stream. Add threshold-crossing ContextUsage events (50%, 70%, 90%) to terminal output for the human watching. The agent self-manages context by calling the tool when it wants.
