session.rs:211 — when a future returns Err, the ? propagates immediately, abandoning all other in-flight futures. Their worktrees are never cleaned up.

## What to do

- Track all created worktrees in a Vec or similar structure within execute_dag
- On error, drain remaining futures and clean up all worktrees before propagating
- Consider a Drop guard pattern that cleans up worktrees if the function exits abnormally
- Ensure the cleanup is best-effort (log warnings, don't fail on cleanup errors)
- Add a test that verifies worktrees are cleaned up when a task errors
- Ensure all tests pass

## Why

Leaked worktrees consume disk space and cause branch collisions on subsequent runs. The current code silently abandons in-flight work.
