## Problem

When rebase fails, the merge-fix agent currently creates a separate temporary worktree (`create_temp_merge_worktree`) because the task worktree was already deleted before merge. After task 59, the task worktree is still alive at merge time, so the merge-fix agent can work directly in it. No temp worktree needed.

## Changes

### merge.rs (attempt_merge_fix)
- Change `worktree_path` parameter to be the task's existing worktree (not a temp one)
- After `rebase_abort` in merge_with_fix, call `attempt_merge_fix(worktree_path, ...)` directly
- The `merge_no_commit(worktree_path, session_branch)` call already works — it merges session_branch into whatever is checked out in the worktree (the task branch)
- On success: get the tip from the task worktree, fast-forward session ref
- On failure: `merge_abort(worktree_path)`, return error

### merge.rs (remove temp worktree functions)
- Delete `create_temp_merge_worktree` function
- Delete `cleanup_temp_merge_worktree` function
- Remove the temp worktree creation/cleanup calls from `merge_with_fix`

### main.rs (Ctrl+C cleanup)
- Remove the `mergefix` worktree branch in `cleanup_worktrees` — these are no longer created
- Simplify the cleanup loop: all worktrees in `.rloop/worktrees/` are regular task worktrees

### merge.rs (build_merge_fix_prompt)
- Update the prompt text: remove mention of 'temporary worktree' or 'rebase was attempted'
- The agent is now working in the task's own worktree with conflict markers from the merge

## Acceptance Criteria
- No `create_temp_merge_worktree` or `cleanup_temp_merge_worktree` functions exist
- No `rloop-mergefix-*` branches are ever created
- Merge-fix agent operates in `.rloop/worktrees/{task_id}/` (the task worktree)
- Ctrl+C cleanup no longer handles mergefix worktree variant
- All existing tests pass
- Clippy pedantic clean
