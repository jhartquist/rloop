When a task is skipped due to a blocked dependency, it is logged as TaskFailed with reason "blocked by failed dependency" (session.rs:312-319). This conflates two distinct states.

## What to do

- Add a new `Event::TaskSkipped { task_id: TaskId, blocked_by: TaskId }` variant to the Event enum in log.rs
- Update session.rs to emit TaskSkipped instead of TaskFailed for blocked tasks
- Add serialization/deserialization handling for the new variant
- Add the new variant to `SessionLogger::print` with appropriate formatting (e.g., yellow "⊘ task 03 — blocked by task 01")
- Add the new variant to the roundtrip serialization test
- Update any tests that count TaskFailed events (they should no longer include skipped tasks)
- Ensure all tests pass

## Why

Log analysis cannot distinguish "tried and failed" from "never attempted" when both use the same event type. This is important for trajectory analysis and the learning loop.
