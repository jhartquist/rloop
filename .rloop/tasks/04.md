Add session exclusivity via lock file. Currently nothing prevents multiple rloop instances from running on the same repo simultaneously, which could cause worktree conflicts, git corruption, and store data races. Add a .rloop/.lock file (or PID-based lock) that is acquired at session start and released on exit. Handle stale locks gracefully (check if PID is still alive). Add cleanup in signal handler and Drop impl. Add tests for lock acquisition, release, and stale lock detection.
