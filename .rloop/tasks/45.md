The cleanup scanner in main.rs:296-321 only handles directories whose names parse as u32. But merge.rs creates worktrees named {id}-mergefix with branches rloop-mergefix-{id}, which are silently skipped.

## What to do

- Generalize `cleanup_worktrees` in main.rs to handle any directory under `.rloop/worktrees/`
- For directories matching `{id}-mergefix`, construct the correct branch name `rloop-mergefix-{id}`
- For plain numeric directories, keep the existing `rloop-wt-{name}` branch logic
- Consider using `git worktree list --porcelain` to enumerate worktrees more robustly
- Add a test or verify manually that merge-fix worktrees are cleaned up on Ctrl+C
- Ensure all tests pass

## Why

Leaked merge-fix worktrees and branches after Ctrl+C during a conflict resolution operation will confuse users and waste disk space.
