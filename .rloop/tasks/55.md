config.rs:140-141 propagates errors without context:
- `fs::read_to_string(&config_path)?` — raw I/O error without mentioning config.toml
- `toml::from_str(&contents)?` — parse error without mentioning which file
- `fs::create_dir_all(rloop_dir.join(subdir))?` in init_rloop_dir — no context on which subdirectory

Similarly, log.rs:207-209 creates session dir and log file without context.

## What to do

- Add `.with_context(|| format!("failed to read {}", config_path.display()))` to the read_to_string call
- Add `.with_context(|| format!("failed to parse {}", config_path.display()))` to the toml::from_str call
- Add `.with_context(|| format!("failed to create {subdir} directory"))` to create_dir_all calls
- Add context to session log file creation in log.rs
- Ensure all tests pass

## Why

Bare ? propagation loses context. When config loading fails, users need to know which file and what operation failed. Compare with task.rs which always adds context — config.rs should be consistent.
