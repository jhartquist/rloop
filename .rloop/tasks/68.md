# Synthesize M1 research and create implementation plan

## Context

Tasks 63-67 produce research findings on Supabase, sqlx, axum, workspace design, and schema. This task reads all findings, resolves any conflicts or dependencies between them, and produces an ordered implementation plan for the rest of Milestone 1.

## What to produce

1. **Research synthesis**: Read all docs in `docs/research/`. Identify:
   - Decisions that are settled
   - Decisions that conflict (one research doc assumes X, another assumes Y)
   - Gaps — things none of the research covered that we still need to decide

2. **Implementation order**: Sequence the actual build work. Consider:
   - What can be done in parallel?
   - What blocks what? (e.g., schema must exist before brain endpoints)
   - What's the smallest useful checkpoint? (e.g., "brain starts and connects to DB" before "brain serves task list")

3. **Task breakdown**: Create concrete implementation tasks (will become rloop tasks 69+). Each task should be:
   - Small enough for one agent session
   - Independently verifiable
   - Clear acceptance criteria

4. **Risk assessment**: What's the riskiest part of M1? Where might we get stuck? What should we prototype first?

## Expected implementation sequence (rough)

This is a starting point — adjust based on research findings:

1. Cargo workspace restructuring (unblocks everything)
2. Supabase init + schema migration
3. DB connection + basic CRUD (tasks table)
4. Brain binary with axum skeleton
5. Brain endpoints: project + task CRUD
6. Brain endpoints: session lifecycle
7. Worker embedded in brain (current step.rs logic)
8. CLI thin client (rewire existing CLI to talk to brain)
9. Event storage in DB (replace JSONL)
10. Integration testing

## Deliverable

Write the plan to `docs/milestone-1-plan.md`. Include:
- Ordered task list with dependencies
- Estimated complexity per task (S/M/L)
- Which tasks can parallelize
- First task to start immediately after plan approval

## Acceptance Criteria

- All research findings incorporated
- No unresolved conflicts between research docs
- Implementation tasks are concrete and sequenced
- Gaps and risks identified
- Plan is ready to be converted to rloop task files
