lock.rs:35-79 has a TOCTOU race: between checking if the lock file exists and creating it, another rloop instance could create its own lock.

## What to do

- Replace `File::create(&path)` with `OpenOptions::new().write(true).create_new(true).open(&path)` which atomically fails if the file already exists
- Handle the "file already exists" error by reading the existing lock and checking for staleness
- Keep the stale-lock PID checking logic
- Add a test that verifies two lock acquisitions fail (the existing `double_acquire_fails` test may already cover this)
- Ensure all tests pass

## Why

The TOCTOU race means two concurrent rloop instances could both acquire the lock and run simultaneously, potentially corrupting the repository. create_new makes the creation atomic.
