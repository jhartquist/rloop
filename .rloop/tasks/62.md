# Show task-attempt format in all terminal output

## Context

Currently, terminal output shows task progress but the attempt number is only visible in StepStarted events. When running parallel tasks or tasks with retries, it's not clear which attempt we're seeing in TaskStarted, TaskCompleted, TaskFailed, and other lifecycle events.

## Requirements

1. **Consistent format**: Display all task events as `task XX-A` where:
   - `XX` is the task ID (zero-padded to 2 digits)
   - `A` is the attempt number (1-indexed, no padding)
   - Example: `task 03-1`, `task 27-2`, `task 99-3`

2. **Events to update**:
   - `TaskStarted`: currently shows `task 03`, should show `task 03-1`
   - `TaskCompleted`: currently shows `task 03 — summary`, should show `task 03-1 — summary`
   - `TaskFailed`: currently shows `task 03 — reason`, should show `task 03-1 — reason`
   - `VerificationRan`: currently shows `verify task 03 \`cmd\``, should show `verify task 03-1 \`cmd\``
   - `WorktreeCreated`: currently shows `worktree 03`, should show `worktree 03-1`
   - `WorktreeMerged`: currently shows `merged 03 → branch`, should show `merged 03-1 → branch`
   - `WorktreeCleanedUp`: currently shows `cleaned up 03`, should show `cleaned up 03-1`
   - `MergeFailed`: currently shows `task 03 merge failed`, should show `task 03-1 merge failed`
   - `MergeFixStarted`: currently shows `task 03 merge-fix agent started`, should show `task 03-1 merge-fix agent started`
   - `MergeFixSucceeded`: currently shows `task 03 merge-fix resolved`, should show `task 03-1 merge-fix resolved`
   - `MergeFixFailed`: currently shows `task 03 merge-fix failed`, should show `task 03-1 merge-fix failed`
   - `StepSummary`: currently shows dimmed `task 03`, should show `task 03-1`
   - `TaskSummary`: currently shows `task 03  done`, should show `task 03  done` (no change — this aggregates all attempts)

3. **Special case - StepStarted**: Currently shows `Task 03  step 1`. Since we're now showing attempt in all events, update to just `Task 03-1` (remove the redundant "step 1", keep model and cc info)

4. **How to get attempt number**: Add `attempt: u32` field to these events:
   - `TaskStarted`
   - `TaskCompleted`
   - `TaskFailed`
   - `VerificationRan`
   - `WorktreeCreated`
   - `WorktreeMerged`
   - `WorktreeCleanedUp`
   - `MergeFailed`
   - `MergeFixStarted`
   - `MergeFixSucceeded`
   - `MergeFixFailed`
   - `StepSummary`

5. **Propagation**: The attempt number is already tracked in `session.rs` in the `execute_task` function. Pass it to all event emissions.

## Acceptance Criteria

- All task lifecycle events display task ID with attempt number in `XX-A` format
- StepStarted event simplified to `Task 03-1` format
- Terminal output clearly shows which attempt each event belongs to
- JSONL logs include attempt field in all relevant events
- All tests updated and passing
- Clippy pedantic clean
